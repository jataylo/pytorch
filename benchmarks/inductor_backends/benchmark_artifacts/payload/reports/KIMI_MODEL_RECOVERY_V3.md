# Kimi official model loader investigation

The shared benchmark environment was not modified. FlyDSL production and frozen workers were not modified.

## Kimi-K3

The original exception chain ends in `ModuleNotFoundError: No module named 'fla'`; official `modeling_kimi_linear.py` wraps this in the generic `Plese run pip install -U fla-core` error. This is a missing optional model dependency, not an Inductor kernel fallback.

Installed only `fla-core==0.6.0`, with `--no-deps --no-compile`, into `optional_model_deps_v3`. The official PyPI wheel is pure Python (`py3-none-any`), contains no binary extension, and depends on existing einops. Wheel SHA256: `b0708b70e0b119cd58a0a5146ea56cb175cef6ed969d8ac60267e3e077ce3ebd`. The manifest lists every installed source/metadata file hash, excluding generated bytecode. Shared imports still report no fla, flash_attn or causal_conv1d.

CPU probe uses the unmodified common.build_model_from_config and actual official remote implementation at revision f831ab66814297da540d832a5235f8e904f29d06. All exact FLA imports succeed. Actual full model construction on meta yields **2,779,931,834,976 parameters**, all meta; buffers total4096; CUDA initializedFalse. It allocates no real model weights. The persistent probe enforces RLIMIT_AS64GiB before importing Torch; CPU-only Triton target discovery is blocked, and Torch GPU initialization raises. These CPU guards belong only in the probe, never the benchmark.

This model needs 5,559,863,669,952 bytes (~5.56TB /5.06TiB) for BF16 parameters alone, before gradients/optimizer/activations, so import success does not imply the full training model fits this host's eight GPUs. Meta construction counts the actual architecture; it does not estimate active-expert capacity or reduce expert count.

Further runtime limitation: official text constructor forcibly changes attention implementation to flash_attention_2 (modeling_kimi_linear.py1109-1119); vision defaults to flash_attention_2 and directly calls flash_attn_varlen_func (modeling_kimi_k3.py83). flash_attn is absent. FLA recovery alone must not be represented as full forward/backward support. Do not install a compiled attention extension in the shared environment while benchmark variants run.

Versioned integration proposal: after worker environment cleanup, for exact `moonshotai/Kimi-K3` only and consistently across all four variants, prepend absolute optional_model_deps_v3 to sys.path/PYTHONPATH before any Transformers import. Record optional manifest digest and actual imported fla path/version in source fingerprint/results. Reuse common's official AutoModel map; no substitute model/config or class registration is necessary for K3. Do not enable FLA globally: installed Transformers can discover it and change other models' attention backend. Keep official source revision pinned.

## Kimi-K3.1-Pro

The official repository at revision d9e99b0792a5e93b78ea9bea62a68167e36ddd9e publishes architecture name KimiK31ForConditionalGeneration and only AutoConfig mapping. Its official repository file inventory includes no modeling Python file. Installed Transformers5.22.1 has no native kimi_k31 model registration. CPU smoke with isolated FLA still fails with the same Unrecognized KimiK3Config AutoModel error. The common loader discards candidate errors, but here the AutoModel implementation itself is unavailable.

No honest class registration fix exists in the published Transformers files inspected. K3.1 adds DSA indexers to the backbone; assigning K3's class would omit those computations. Do not alias it. The official README's documented deployment choices are vLLM, SGLang and TokenSpeed inference engines; those are not training implementations. Record this model as unsupported_official_training_implementation, with original traceback, unless a genuine upstream training implementation becomes available. Do not report a parameter count for a model that was not constructed.
